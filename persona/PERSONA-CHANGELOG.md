# 人格变更日志（小羽）

记录**人设内容与人格行为**的变化，方便回溯"她为什么变成现在这样"。

约定：

- 每次改角色卡正文，都在最上面加一条：**改了什么 + 为什么 + 影响**，不贴大段原文；
- 改角色卡正文标 `[人设]`；接线/解析/测试这类不动文字的改动标 `[行为]`；
- **人格运行数据不在本仓库**（记忆/日记/心情在 `~/.dsh-qqbot/persona/app-<appId>/`，
  随账号走，不随代码走）。

## 角色卡在哪

| 文件 | 角色 |
|---|---|
| `persona/rolecard-xiaoyu.md` | **正本**，入库，改人设就改它 |
| `~/.dsh-qqbot/persona/rolecard-default.md` | 符号链接 → 正本（profile 的 `roleCardPath` 指这里） |
| `persona/role.example.md` | 通用模板（给别人的示例），**不是**小羽的卡，别当她的改 |

生效方式：`Role.read()` 带 5 秒缓存——**改完最多 5 秒生效，不用重启、不用重载插件**。

## 怎么改人设

1. 改 `persona/rolecard-xiaoyu.md`；
2. 在本文件最上面加一条 `[人设]` 记录；
3. `git add -A && git commit -m "persona: ..."` 并推送；
4. 等 5 秒，验证：私聊一句看她语气；或跑
   `node -e "import('./lib/persona/role.js').then(m=>console.log(new m.Role({cardPath:'persona/rolecard-xiaoyu.md'}).lint()))"`。

> 改法原则（与主人约定）：**只给边界，不指定方向**。行为问题优先改角色卡
> （5 秒生效、不动代码），而不是改参数或硬编码文案。
>
> ⚠️ 多会话并行改人设时：**先 `git pull`、先 `diff` 线上卡和正本再动手**。
> 线上是软链时改动直接落在正本上，两个会话互相覆盖是静默的（见 11-04 记录）。

2. **`roleCardPath` 支持 `~/` 与相对仓库根**（`resolveCardPath`）：
   绝对路径原样；`~/...` 展开主目录（此前按字面文件名读、必然 ENOENT 且静默）；
   其余按仓库根解析（`repoRoot()` 与 sticker-tool 同一套 fileURLToPath 办法，
   不依赖进程 cwd）。`persona/rolecard-xiaoyu.md` 这种写法从此仓库搬家不断链。
   lint 报"读不到"时会把**解析后的实际路径**一起带出来，排查不用再猜。
3. 顺手修一个测试 flaky（非人设）：`@ 必醒 / 名字必醒 / owner 不@也潜水`
   没关默认 0.05 的随机放行，约 7% 翻车 → 显式 `probability: 0`。
